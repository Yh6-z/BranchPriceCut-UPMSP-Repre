# C# 与 Python 求解结果比较

核对日期：2026-10-15。按数据来源、机器数、作业数、实例号和加工时间精度匹配，
不能仅凭 `12_60_TWCT_1` 文件名匹配。比较的是 C# 项目保存的 Excel 结果；本次没有重新运行 C#。

## 完整求解结果

| 数据集 / 实例 | C# 目标值 | Python UB | Python LB | 目标差 | 判断 |
|---|---:|---:|---:|---:|---|
| C# 原始整数数据，12×60，第 1 个 | 16347 | 16347 | 16347 | 0 | 一致 |
| JD 一位小数，12×60，第 1 个 | 881 | 881 | 881 | 0 | 一致 |
| JD 二位小数，12×60，第 1 个 | 857.69 | 857.69 | 857.6899999999999 | 0 | 一致，LB 差异为浮点误差 |

对以上三组逐项核对了 Python 保存的全部权重及加工时间与相应 Excel 输入相同。
分别读取 C# 与 Python 的机器调度，从原始加工时间累加每个作业的完工时间并计算
$\sum_j w_j C_j$，独立复算均与记录目标相符；两端都恰好覆盖所有 60 个作业。
目标比较与复算采用 $10^{-6}$ 绝对容差，输入矩阵与作业编号使用精确比较。

## 调度与初始解

| 数据集 | 机器分配相同的作业数 | 作业序列完全相同的机器数 | C# 初始上界 | Python 初始上界 |
|---|---:|---:|---:|---:|
| 原始整数数据 | 59/60 | 10/12 | 19457 | 19457 |
| JD 一位小数 | 60/60 | 11/12 | 1556.8 | 1256.4 |
| JD 二位小数 | 60/60 | 12/12 | 1232.73 | 1232.73 |

原始整数数据的两份调度都可行、目标都为 16347，属于不同的同目标调度。

JD 一位小数仅第 12 台机器的顺序不同：C# 为 `(30, 23, 28, 50)`，
Python 为 `(23, 30, 28, 50)`。作业 23 的 $p/w=0.2/2$，作业 30 的
$p/w=0.3/3$，数学上均为 0.1，交换两者不改变总加权完工时间。
IEEE 双精度计算分别为 `0.1` 与 `0.09999999999999999`，而 Python 的 SWPT
使用精确有理数并按作业编号处理并列。

初始上界差异也已直接复现：对同一 JD 一位小数输入执行 C# 的浮点比值轮转列表调度得到
1556.8；执行当前 Python 的精确比值规则得到 1256.4。因此初始调度没有逐项复刻 C# 的浮点并列行为，
但最终解的目标一致。本次比较没有更改任何求解或排序代码。

## 运行过程与耗时

| 数据集 | C# 保存耗时（秒） | Python 本次耗时（秒） | C# CG 迭代数 | Python RMP 求解次数 |
|---|---:|---:|---:|---:|
| 原始整数数据 | 5.112 | 107.476 | 92 | 68 |
| JD 一位小数 | 4.440 | 172.258 | 62 | 69 |
| JD 二位小数 | 5.277 | 185.743 | 83 | 68 |

Python 记录明显更慢，过程次数也不同。C# 的 CG 计数与 Python 的 RMP 次数不保证同口径。
Python 这三次均关闭邻域启发式，且未实现对偶平滑；初始列、每轮加入的列数量、实现方式、
硬件和运行环境也未控制一致。这些历史耗时不能作为同配置的语言性能倍数。

三个完整实例均在根节点列生成后收敛，没有实际触发割、固定删弧或强分支。
因此本次实算支持“这三个实例的最终目标正确”，不能扩展为“所有实例、所有 BPC 技术均已与 C# 完全一致”。
20×200 一位小数的 C# 记录实际使用了 2 轮 CCG、17466 条删弧及 4 个搜索节点，
后续应作为完整 BPC 技术的重点对照实例。
